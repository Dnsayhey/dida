# 软件结构与运行流程

这份文档描述仓库里 `src/` 代码当前的软件结构、启动流程和交互行为。更偏硬件的信息见 [硬件适配说明.md](./硬件适配说明.md)。

## 1. 项目定位

当前项目是一个运行在 `AirM2M Core ESP32-C3` 上的小屏天气设备：

- 使用 `LVGL` 绘制 240x320 竖屏界面
- 使用 `Wi-Fi` 获取天气和时间
- 使用光敏传感器自动调节背光
- 使用单个外接实体按钮完成页面切换
- 屏幕没有触摸能力

硬件事实以 [硬件适配说明.md](./硬件适配说明.md) 为准。

## 2. 当前主流程

入口在 [../src/main.cpp](../src/main.cpp)。当前 `main.cpp` 已经很薄，只负责：

- 初始化串口
- 调用 `AppRuntime::begin()`
- 创建 `lvgl_task`
- 创建 `init_and_api_task`

### `AppRuntime::begin()`

位于 [../src/app/app_runtime.cpp](../src/app/app_runtime.cpp)，当前负责：

- 初始化 `AppController`
- 如果启用 `DEV_MODE`，应用本地开发默认配置
- 初始化显示设备

### `lvgl_task`

由 `AppRuntime::runUiTaskLoop()` 承接，主要负责：

- 初始化页面系统
- 初始化按钮输入
- 初始化背光和光敏背光任务
- 循环处理 LVGL timer
- 轮询实体按钮

### `init_and_api_task`

由 `AppRuntime::runDataTaskLoop()` 承接，主要负责：

- 执行 `StartupFlow`
- 等待 Wi-Fi 配置
- 连接 Wi-Fi
- 确认城市 location ID
- 注册 NTP、实时天气、实时空气质量、未来天气和日志任务
- 周期运行 `TaskManager`

## 3. 当前模块状态

### 应用层

当前应用层位于 [../src/app](../src/app)。

主要模块：

- `AppRuntime`：运行时总装配，连接 UI 任务、数据任务、按钮、背光、启动流程。
- `StartupFlow`：启动后的 SoftAP 配网、网络、城市 ID、任务注册和启动导航流程。
- `ProvisioningPortal`：无 Wi-Fi 配置时启动 SoftAP、DNS 和网页表单，保存 Wi-Fi 与天气位置。
- `AppController`：应用状态记录，以及把按钮事件转换成 `AppCommand`。
- `AppCommandExecutor`：把 `AppCommand` 落到页面切换或页面内部事件。
- `DeviceConfigProvider`：启动配置、Wi-Fi 配置状态、location ID、开发默认配置内容和工厂重置入口。
- `DeviceSettingsStore`：设备 UI 设置持久化，包括背光模式和浅色/深色主题。
- `DeviceSettingsController`：亮度与主题页交互入口，负责亮度模式文案、亮度切换和主题切换。
- `WeatherDataClient`：隔离应用层和底层天气服务。
- `WeatherDataSync`：城市 ID、经纬度、实时天气、实时空气质量和未来天气同步编排。
- `WeatherTaskRegistrar`：周期任务注册。
- `WeatherViewDataProvider`：天气页面只读展示数据入口、同步状态读取和展示文本格式化。

### 页面系统

页面管理器位于 [../src/pages/page_manager.cpp](../src/pages/page_manager.cpp)。

当前页面包括：

- 初始化页
- 配网页
- 实时天气页
- 未来天气页
- 亮度与主题页
- 恢复出厂页

当前页面系统已经具备：

- `BasePage` 统一页面基类
- 透明全屏页面 helper
- 浅色/深色主题统一应用
- 居中文案 helper
- 半透明卡片 panel helper
- 中文 UI 字体挂载 helper
- 页面创建、显示、隐藏和当前页面内部事件分发

页面切换决策不再放在 `PageManager` 中，而是由 `AppController` 产生 `AppCommand` 后交给 `AppCommandExecutor` 执行。

### 配置管理

[../src/config/config_manager.cpp](../src/config/config_manager.cpp) 是底层 NVS 读写实现，当前支持：

- Wi-Fi SSID 和密码
- 地区信息
- 位置名称
- location ID
- 背光模式
- 主题模式

应用代码优先通过以下入口访问配置语义：

- `DeviceConfigProvider`
- `DeviceSettingsStore`

补充说明：

- 当前如果启用了 `DEV_MODE`，会为缺失配置项补充本地开发默认值
- 已存在的配置不会被 `DEV_MODE` 无条件覆盖
- DEV_MODE 默认值通过本地忽略配置注入，底层 `ConfigManager` 只负责 NVS 读写

### 网络与请求

- [../src/net/network_manager.cpp](../src/net/network_manager.cpp) 负责 STA 模式连接 Wi-Fi。
- [../src/net/network_status.cpp](../src/net/network_status.cpp) 负责提供网络状态查询入口。
- [../src/net/request.cpp](../src/net/request.cpp) 负责 GET 请求、超时、简单重试和 URL 编码。
- `StartupFlow` 通过 `NetworkConnector` 连接 Wi-Fi，不再直接依赖 `NetworkManager`。
- `Request` 通过 `NetworkStatus` 判断联网状态，不再直接依赖 `NetworkManager`。

### 天气服务

[../src/weather/weather_service.cpp](../src/weather/weather_service.cpp) 当前支持：

- 城市查询
- 实时天气
- 实时空气质量
- 7 日天气

当前约定：

- 天气同步流程通过 `WeatherDataSync` 调用。
- 页面展示通过 `WeatherViewDataProvider` 读取。
- `WeatherSyncResult` 记录最近一次同步状态，当前页面可区分同步中、成功和失败。
- 城市查询会保存 `location_id` 和经纬度；实时空气质量使用经纬度请求。
- 页面不直接依赖 `WeatherService` 或 `ConfigManager`。

### 硬件控制

- [../src/hardware](../src/hardware)：显示设备、实体按钮、背光 PWM、光敏读取和光敏背光策略。

固定引脚和周期常量集中在 [../src/board/board_config.h](../src/board/board_config.h)。

## 4. 当前启动与交互

启动入口位于 [../src/main.cpp](../src/main.cpp)，当前流程可以概括为：

1. `setup()` 初始化串口，调用 `AppRuntime::begin()`，创建 UI 任务和数据任务。
2. `lvgl_task` 初始化页面、按钮、背光，并循环处理 LVGL timer 和按钮轮询。
3. `init_and_api_task` 执行 `StartupFlow`，完成 SoftAP 配网、Wi-Fi 连接、城市 ID 与经纬度确认、天气/空气质量/NTP 任务注册和启动后页面切换。

当前页面枚举：

| 页面 | 用途 | 当前状态 |
| --- | --- | --- |
| `PAGE_INIT` | 初始化页面 | 已实现 |
| `PAGE_NETWORK_SETUP` | SoftAP 配网页 | 已实现 |
| `PAGE_REAL_TIME_WEATHER` | 实时天气页 | 已实现 |
| `PAGE_FUTURE_WEATHER` | 未来天气页 | 已实现 |
| `PAGE_THEME_SETTINGS` | 亮度与主题页 | 已实现 |
| `PAGE_FACTORY_RESET` | 恢复出厂页 | 已实现 |

按钮输入由 `hardware/ButtonInput` 封装，应用决策由 `AppController` 负责，页面执行由 `PageManager` 完成。

| 页面 | 单击 | 双击 | 长按 |
| --- | --- | --- | --- |
| `PAGE_INIT` | 无 | 跳到 `PAGE_REAL_TIME_WEATHER` | 无 |
| `PAGE_NETWORK_SETUP` | 无 | 跳到 `PAGE_REAL_TIME_WEATHER` | 无 |
| `PAGE_REAL_TIME_WEATHER` | 跳到 `PAGE_FUTURE_WEATHER` | 跳到 `PAGE_THEME_SETTINGS` | 无 |
| `PAGE_FUTURE_WEATHER` | 跳到 `PAGE_REAL_TIME_WEATHER` | 跳到 `PAGE_THEME_SETTINGS` | 无 |
| `PAGE_THEME_SETTINGS` | 切换亮度模式 | 跳到 `PAGE_FACTORY_RESET` | 切换浅色/深色主题 |
| `PAGE_FACTORY_RESET` | 无 | 跳到 `PAGE_REAL_TIME_WEATHER` | 清理 NVS 并重启 |

- 单击：
  实时天气页和未来天气页互相切换；亮度与主题页切换亮度模式。
- 双击：
  天气页进入亮度与主题页，亮度与主题页进入恢复出厂页，恢复出厂页返回实时天气页。
- 长按：
  亮度与主题页切换浅色/深色主题；恢复出厂页执行恢复出厂设置。

文案约束：只有真实实现的动作，才能写到页面提示文案里。

## 5. 当前状态

### 已经可用

- 固定硬件参数已集中到 `board/`。
- 显示、按钮、背光、光敏和光敏背光策略位于 `hardware/`。
- 应用状态、启动流程、任务注册、天气同步和按钮命令位于 `app/`。
- DEV_MODE 默认配置内容通过本地忽略配置注入，不提交私人配置。
- 页面层不直接读取 `ConfigManager` 或 `WeatherService`。
- 实时天气页已经展示天气、温度、体感、湿度、风力、能见度和空气质量。
- 页面 UI 已经统一成适配无触摸屏的小卡片风格。
- 中文字体通过 `ui_zh_20` 专用字库处理。

### 仍需继续产品化

- 配网页已具备 SoftAP 表单配网和 Wi-Fi 下拉选择，但联网失败后的设备端反馈还可以更明确。
- 恢复出厂页已支持长按清理 NVS 并重启，后续可以继续优化确认文案和防误触体验。
- 亮度与主题页已支持亮度档位和浅色/深色主题切换，后续可以继续打磨视觉细节。
- 天气和空气质量同步状态已经能区分同步中、成功和失败，但页面暂时只显示简短失败文案，详细失败原因仍主要在串口日志。
- 天气 API Base URL 和 API Key 已从可提交源码移到天气配置宏，正式配置流程仍需继续收口。
- 当前还没有自动测试用例。

## 6. 后续路线

如果继续推进，建议优先级如下：

1. 配网体验
   在现有 SoftAP 配网页基础上补齐联网失败反馈、重试入口和重新配网入口。
2. 恢复出厂体验
   继续打磨长按确认文案、执行反馈和重启前提示，确保高风险操作不会被误触。
3. 天气错误状态
   继续细分网络失败、HTTP 失败、解压失败、解析失败和 API 无数据，并在有旧数据时优先展示旧数据。
4. 配置与密钥
   继续收口开发默认配置和正式配置流程，避免私人环境配置固化在公共源码里。
5. 最小测试
   先补天气解析、URL 编码、任务调度和配置策略等不依赖硬件的自动回归。
6. 文档与测试
   保持 README、硬件文档和本软件结构说明同步，并补齐不依赖硬件的自动回归。
